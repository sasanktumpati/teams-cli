teams {version}: local-first SQLite archive, CLI, and scoped HTTP API for macOS Microsoft Teams.

Conventions
  --json on commands matches the HTTP API shape.
  Chats (--chat, chat export, msg list/send) & people (--from, --mention) accept a name fragment, email, or id.
  Messages on live actions accept numeric MSG_ID or chatId/msgId (use --chat if a numeric id collides).
  Times (--since/--until): 30m 12h 7d 2w today yesterday 2026-11-01 2026-11-01T14:00 (local); --since all clears default 7d windows.
  --limit 0 = unlimited; "matched" is total count, "truncated": true means more exist.
  Search: prefix words, "exact phrase", OR, NOT, -exclude / -"phrase"; --relevance weights subject > body.
  Exit codes: 0 ok, 1 runtime/archive/auth/policy error, 2 bad input. Errors go to stderr.

HTTP API (127.0.0.1:{port}, loopback Host only, no Origin)
  GET /health (open); all /v1/* require `Authorization: Bearer <token>` (`teams token create <name> --scope ...`).
  Scopes (default: read):
    read           GET /v1/* archive reads + GET /v1/live/status
    sync           POST /v1/sync
    presence:read  GET /v1/live/presence
    presence:write POST /v1/live/presence/{set,message}
    react          POST /v1/live/messages/{react,unreact,pin,unpin,save,unsave} + /v1/live/chats/{mute,unmute}
    mark-read      POST /v1/live/chats/{read,unread}
    send           POST /v1/live/messages/{send,forward}
    modify         POST /v1/live/messages/{edit,delete}
    chat:manage    POST /v1/live/chats/{create,rename,add-member,remove-member}
  Daemon live writes also require `teams daemon install --allow-writes` (or `teams daemon run --allow-writes`).
  Optional per-token chat allowlist for live chat write actions (archive reads are not chat-filtered): `teams token create <name> --scope send --chats "Engineering,48:notes"`.
  HTTP live routes resolving chat/person names, bare messageIds, or quote/forward also require `read` scope (exact chat IDs, MRIs, and chatId/msgId work without `read`).
  Archive GET routes (camelCase query params):
    status, chats(query member kind includeSystem), messages(chat|around context sender thread history),
    search(query history countOnly hasAttachments sender chat sort=relevance), files|attachments, people, person(person),
    changes(what=edited|deleted), records(source key allVersions), inbox, mentions(chat unreadOnly), calls(person missedOnly),
    meetings(query), saved(includeUnsaved), pinned(chat); since/until/limit/includeEvents as in CLI.
  Live routes (Content-Type: application/json; strict schema; optional Idempotency-Key header):
    GET  /v1/live/status
    GET  /v1/live/presence?person=...
    POST /v1/live/messages/{send,edit,delete,react,unreact,pin,unpin,save,unsave,forward}
    POST /v1/live/chats/{create,rename,add-member,remove-member,read,unread,mute,unmute}
    POST /v1/live/presence/{set,message}
  Errors: {error: {code, message, details?}} (401 unauthorized, 403 scope_required/chat_not_allowed/writes_disabled,
    409 sync_busy/empty_archive/ambiguous_target, 429 rate_limited, 503 migrating/live_auth_unavailable/teams_session_expired).

Write Guardrails
  High-impact CLI actions (msg send/edit/delete/forward, chat new/rename/add-member/remove-member):
    dry-run by default unless --yes AND TEAMS_CLI_ENABLE_WRITES=1 (optional TEAMS_CLI_WRITE_ALLOWLIST).
  Low-impact CLI actions (msg react/unreact/pin/unpin/save/unsave, chat read/unread/mute/unmute, presence set/message):
    run directly (pass --dry-run to preview).
  All live writes append a metadata-only JSONL audit entry (no message bodies) to write-audit.jsonl and return archiveVisible: false.
